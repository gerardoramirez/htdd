# Release log

High-level record of the governing milestone named in `CURRENT.md`.

This file holds only that milestone's entries. It is the hot window, not the lifetime history.

Build work reads the governing milestone. It does not read this log to discover what to do. Read an entry here only when troubleshooting names this milestone.

When a milestone is completed, or materially updated, append a short entry below, newest first. Write the same entry under `Release` in that milestone's `MILESTONE_SUMMARY.md`.

Still in force names the exclusions this product binds. A later milestone restates the exclusions that remain from its predecessor, or names the predecessor file in `AREAS.md`. A sentence that only names the predecessor is not that list. A first milestone names the exclusions it binds. Do not point `CURRENT.md` at a folder until that list is written. Do not copy another product's exclusions into the list. `001_EXAMPLE_MILESTONE` is a template, not the governing milestone.

When that milestone is archived, move its entries to `archive/RELEASE_LOG.md`. Leave this file for the new governing milestone.
