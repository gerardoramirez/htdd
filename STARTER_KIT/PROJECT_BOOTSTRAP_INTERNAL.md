# Project Bootstrap

This is meaning research, not market research.

This page is for work a team holds. That includes an internal product, and a product whose user is not the person at the far end. Fill this page only when `PROJECT.yaml` sets `bootstrap` to `internal_b2b`. If it says `founder`, use [PROJECT_BOOTSTRAP.md](PROJECT_BOOTSTRAP.md) and leave this file blank.

Begin here after [INIT.md](INIT.md). Every later artifact in this folder should be traceable to what you write on this page.

If this file is still incomplete and the governing milestone named in `MILESTONES/CURRENT.md` has a complete implementation artifact chain, implementation may proceed from that chain. Do not invent a team's experience, a person at the far end, or success language to fill this page. Incomplete bootstrap is later human work, not an implementation blocker when the milestone chain is already complete.

Mark any line you cannot answer yet with `[open]`. Leave it open. An agent must not close an `[open]` by writing an answer.

## Whose experience

Name the team, and name the person whose experience is being recorded.

A team-owned product records that person's experience. It does not invent a founder.

---

## What happened

What happened that made this problem impossible to leave alone?

A dramatic event counts. So does a recurring operational pain.

One dramatic example: a day when a person was harmed, or a promise was broken, and the old way could not be resumed.

One operational example: a process the team repeats, where the same failure shows up every cycle, and leaving it in place has become a decision.

Write the one that is yours. Write both when both are true.

---

## The people

Who uses the product? Name the direct user.

Who is the person at the far end of this chain? They may never open the product. Name them too.

If they are the same person, say so.

---

## What would be lost

If this product disappeared tomorrow, what would the direct user lose?

What would the person at the far end lose?

Answer for both. When someone else bears the result, an answer about only the person who signs in is unfinished.

---

## What changes

Who, specifically?

Write that name on the first line, before any capability.

Then write the before and the after for that person.

"Their ability to do X" names a capability. The person comes first. The change comes second.

## Success

How do you hope the person at the far end, or the people who act on their behalf, would describe what this team protected?

A twenty-year description of a company is optional. A team that does not think of itself that way can answer for the practice instead.
