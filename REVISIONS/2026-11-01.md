# 2026-11-01

One product ran a quality pass while the milestone was still a planning draft. The product repository had no `MILESTONES/CURRENT.md`. Its agent file named an older milestone and told agents to sort `MILESTONES/`. The work changed scope and copy without updating the milestone record. A test that locked a governed sentence stayed red.

Nothing here is a new Human Truth. Logged as [DISC-011](../DISCOVERIES/DISCOVERIES.md).

---

## What was accomplished

The stops are now explicit in [Product Gravity](../METHODOLOGY/PRODUCT_GRAVITY.md), [Prototype Practice](../METHODOLOGY/PROTOTYPE_PRACTICE.md), and the starter-kit operating rules.

If a product `AGENTS.md` names a milestone folder, or tells an agent to sort `MILESTONES/`, and `MILESTONES/CURRENT.md` is missing or names a different folder, implementation stops. The agent file is stale. Do not guess the newest folder.

A milestone cannot become governing until it has `MILESTONE_SUMMARY.md` and a short still-in-force list. That list names the exclusions this product binds. A later milestone restates the exclusions that remain from its predecessor, or names the predecessor file in `AREAS.md`. A sentence that only names the predecessor is not that list. A first milestone names the exclusions it binds. Do not copy another product's exclusions into the list.

A quality-pass milestone cannot add a surface, collection, access path, invitation channel, or discovery query. If the work needs one, stop. Open a new milestone first. This is an implementation stop.

A change to a sentence, a route purpose, or an access rule that appears in a governing contract is a contract change. The same change updates the milestone status record. Code that disagrees with the contract is not done. Updating a test to match warmer copy, without that record, is a contract change done backwards.

Warmer copy is a Product Gravity check. A refusal or a replacement names the ordinary product move and the positive designed object. Reassurance (“that’s okay”) and a pointer at future contribution are ordinary product moves inside an empty moment the experience was meant to hold.

A ticket is not implemented while a test that locks its contract is red. A follow-up commit that fixes a syntax error, a crash, or a dependency pin from the previous pull request means that pull request did not close.

## What practice kept

A quality pass still restates the milestone's job. A defect still stays inside the current shell. Markdown governance still wins when code comments drift. A refusal still names a positive designed object.

The product story that taught these rules stays in that product. These pages keep the operating pattern only.

## What was deliberately not claimed

This is one product's miss during a quality pass. It is not validated on a second product. It is not a Human Truth. It adds no new glossary term. The Product Gravity entry now includes the warmer-copy check.

## Existing product repositories

Projects that already copied the kit do not receive this by refreshing `METHOD/`. Add `CURRENT.md`, `AREAS.md`, and `RELEASE_LOG.md`. Point `CURRENT.md` only after the new milestone names the exclusions this product binds. Replace any `AGENTS.md` that hardcodes a milestone folder with the current `AGENTS.md`. If an older copy lists another product's exclusions, replace that sentence with this product's own list. Do not overwrite filled milestone work.
