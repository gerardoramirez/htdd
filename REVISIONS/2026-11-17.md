# 2026-11-17

A new copy of the starter kit now begins with three questions. The answers choose the bootstrap and whether the first milestone is an experience arc.

Nothing here is a new Human Truth. Nothing here is a case study.

---

## What was accomplished

[INIT.md](../STARTER_KIT/INIT.md) is the first sitting. A person answers. An agent may record the answer and may not choose it.

[PROJECT.yaml](../STARTER_KIT/PROJECT.yaml) holds three values, all shipped `unset`:

- `builder` is `skilled_builder` or `learning_the_ropes`. It is about the person sitting with the work. It is kept so later guidance can meet that person. It does not choose a bootstrap or an artifact chain, and this revision does not write a second agent manual from it.
- `bootstrap` is `founder` or `internal_b2b`. The founder page stays [PROJECT_BOOTSTRAP.md](../STARTER_KIT/PROJECT_BOOTSTRAP.md). A team, including an internal product or a product whose user is not the person at the far end, fills [PROJECT_BOOTSTRAP_INTERNAL.md](../STARTER_KIT/PROJECT_BOOTSTRAP_INTERNAL.md). The other file stays blank.
- `experience_arc` is `true` or `false`. `false` lets a milestone govern without the state map, transition spec, guardrail checklist, review script, beats, gifts, or an Arc Steward. The exclusions, the status record, and the ticket completion classes still apply. An agent must not invent an arc to fill the folder.

Both bootstraps say where "Why this?" may name the product, offer starters for "what would have to be true," and recognize `[open]` as a line an agent must not close. The internal page asks for the direct user and the person at the far end, and it asks for a named person before a capability. The example milestone shows how a human can find the first exclusions, with an illustration that is not a list to copy. A draft milestone folder may be renamed until `CURRENT.md` points at it.

## What practice kept

A first milestone still names the exclusions that product binds. Another product's list is still not copied forward. A quality pass still cannot widen the product. A stale agent file still stops implementation. The registry is still empty.

## What was deliberately not claimed

This does not validate a Human Truth. It does not publish a case study. It does not change a product that already governs without `PROJECT.yaml`. A missing file is not `experience_arc: false`. It does not make `learning_the_ropes` a simpler method. The label is only recorded.

## Existing product repositories

Projects that already copied the kit do not receive this by refreshing `METHOD/`. They may add `INIT.md` and `PROJECT.yaml` beside the filled bootstrap and set `bootstrap` to the page already in use. Do not overwrite that page. Do not set `experience_arc` to `false` on a milestone that already uses the arc files.
