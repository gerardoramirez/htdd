# 2026-09-26

Milestones stay the unit of focus. The starter kit now keeps that focus from becoming a full history load.

Nothing here is a new Human Truth. It is an operating rule for agent attention.

---

## What was accomplished

`MILESTONES/CURRENT.md` names the governing milestone. Agents read that file, then only that folder. They do not sort `MILESTONES/` to guess, and a later review folder cannot silently take the implementation artifacts.

A release entry records high-level work when a milestone is completed or materially updated. The same entry lives on the milestone summary and in `MILESTONES/RELEASE_LOG.md`. That log holds only the governing milestone.

Closed milestones move to `MILESTONES/archive/`. Their release entries move with them. Agents do not read the archive unless `CURRENT.md`, `AREAS.md`, or the user names a file.

`MILESTONES/AREAS.md` points at the last file for each product area. Troubleshooting opens that file, then at most the one predecessor named on the release entry.

---

## What was deliberately not claimed

This does not shrink living truth. Truths, principles, bootstrap, and the boards in play stay in the default read.

A release log that must be read from top to bottom would be the same overload as loading every milestone. The hot log stays on the governing milestone.

Projects that already copied the kit do not get this by refreshing `METHOD/`. Copy the new blank files into `MILESTONES/`. Do not overwrite filled milestone work.
